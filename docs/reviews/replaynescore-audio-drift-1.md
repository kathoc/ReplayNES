# ReplayNESCore 連続音声: 描画オフのフレームで音声数が時間軸とずれる（2026-10-24）

## 症状

`replaynes-cli dump-audio "roms/Super Mario Bros. (World).NES" --core replaynescore --frames 20`
が 15 フレーム目（0 起点）で
`error [internal]: ReplayNEScore continuous audio count disagrees with frame timeline` で止まる。
12 フレームまでは通る。ctest（新コアあり 34/34、既定 32/32）はすべて通るので、試験では検出されていない。

## 実測（stepFrame 終了時に lastAudioSlot / pendingAudio / cursor を出力した計測用コピー）

```
frame cpu     dcyc  pending want cursor ideal
0     29780         798     798  798    798
1     59561   29781 799     799  1597   1597
2     89342   29781 799     799  2396   2396
3     119122  29780 798     798  3194   3194
...
14    446710  29781 799     799  11980  11980
15    476490  29780 799     798  12779  12778   <- ここで不一致
```

## 原因

- `audioSamplesBefore()` の時間軸は 1 フレーム = 655171/22 = 29780.5 CPU サイクル（描画あり・奇数フレーム 1 ドット短縮の平均）を前提にしている。
- 描画オフのフレームは短縮が起きず 341×262/3 = 29780.67 サイクル。マリオの起動直後はこの状態で、実測も 29780/29781/29781 の繰り返し。
- CPU クロック基準の連続リサンプラは実機時間に従って進むので、理想時間軸より 1 フレームあたり約 0.17 サイクル先行する。15 フレームで +2 サイクルずれ、cursor が整数をまたいで 1 サンプル多くなる。
- 現アダプタはフレームごとの完全一致を要求するため、正当なフレーム長の違いを異常として止まる。描画オフが続く限りずれは際限なく増える。
- 試験用 ROM は最初から描画していて平均がちょうど 29780.5 になるため、ctest では表に出ない。
- `docs/plans/2026-10-24-replaynescore-continuous-audio.md` の検討案 14 は繰越を「frame時刻不一致を隠す」として不採用にしているが、フレーム長の違いは実機の正当な挙動で、この判断の前提が誤っている。

## 修正の方向（ReplayNES 利用者と合意済み）

- フロントエンドはフレームを固定レート（39375000/655171 Hz）で提示し、ICore の契約もフレームごとに `audioSamplesForFrame(frame)` 個を返すことなので、**各フレームで実際に進んだ CPU slot 列を、そのフレームに割り当てられた出力区間 [audioSamplesBefore(f), audioSamplesBefore(f+1)) へ写す**。
- 位相・面積・DC 履歴はフレームをまたいで保持し、フレーム境界で切らない。フレーム長に応じて写像の比率が変わるだけにする（描画オフ時の音程差は約 0.0006%）。
- 見送り: ずれを次フレームへ繰り越す方式。暗転が長いと遅延が際限なく溜まる。
- 整数・決定的・save/load と soft reset で連続、という既存の要件は維持する。
