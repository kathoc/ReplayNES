# ReplayNESCore 音量調査・回帰試験計画

## 目的と要件

Nestopia を基準に、単独 pulse1 / pulse2 / triangle / noise / DMC と混合音の振幅差を測定する。入力は生成した既知の NROM 波形と、volume-1.md と同じ SMB 600 frames / start@120+4。int16 尺度、チャンネル比、ミキサー、アダプタの寄与を切り分ける。

ReplayNEScore 本体は参照のみ、sources.md は変更しない。出力と Release / Unix Makefiles ビルドは /tmp。push しない。本体の原因ならホストで補正せず CORE_SELECTION_PLAN.md の Codex 依頼節へ根拠を追記する。

## 検討案と優先順位

|優先|案|効果|難度|採否・理由|
|---:|---|---|---|---|
|1|定常単独波形の ROM を生成|チャンネル比を直接測る|中|採用|
|2|異なる音量の pulse と混合音を測る|非線形性を分離|低|採用|
|3|コアの式・定数を数値予測と照合|尺度と混合式を特定|中|採用|
|4|既存アダプタの独立 oracle 試験を実行|ホスト演算を検証|低|採用|
|5|SMB の秒別 RMS を再測定|元症状を再現|低|採用|
|6|ホストへ一律2倍を追加|聴感の差を短縮|低|不採用。原因特定にならず比率差を隠す|
|7|DC フィルタを変更|低域の差を縮小する可能性|中|原因と確認できない限り不採用|
|8|外部本体を直接編集|根本修正の候補|中|本タスクでは禁止|
|9|既知波形と許容比を回帰試験化|再発・修正確認を自動化|中|採用。未修正時の失敗は隠さない|
|10|新規スキル・独立自動化基盤|手順再利用|高|不採用。リポジトリの試験と測定手順へ集約する|

## 手順と完了条件

1. コード経路調査と既知波形の試験を分担し、式による予測と実測を照合する。
2. 原因箇所に従いホスト修正または外部コアへの依頼を記録する。
3. Nestopia との定常 RMS 比の許容範囲を 0.90〜1.10 とする回帰試験を追加する。無音・クリップ・波形生成の異常も検出する。現在の不具合に合わせて閾値を広げない。
4. 新コアあり・既定の両構成で全 ctest を実行し、SMB 秒別 RMS 比を報告する。本体修正が必要で回帰試験が失敗する場合は受け入れ未達と明記する。
5. docs/reviews/replaynescore-volume-2.md に測定条件、結果、判断、確認範囲、未達事項を残す。

## 実施結果と仕様との差異

定常波形の尺度・ミキサー式差を実測で特定し、本体側の依頼をCORE_SELECTION_PLANへ追記した。本体・ホストの音量処理や互換識別子は未変更。
回帰試験は9種完走し8件の音量比違反を検出。既定33/33、新コアの既存34件は通過し、新規音量試験だけが不合格。
新試験は120 frames×9本に450秒を要したため、試験の時間上限は300秒から900秒へ設定。初回timeout後に単独で完走し、RMS許容範囲は変更していない。
SMBの元実測を再現し、同一tupleでの式交換・DC逆変換も実施したが、SMBの全量および定常全混合の残差は未解明。
音量の受け入れは未達のため、別ジョブの本体修正後に再検証する。最終表とコマンドは `docs/reviews/replaynescore-volume-2.md`。

## 0.9.1 同期とホスト尺度統一（2026-10-24 追加）

上記の本体への尺度変更依頼は利用者の確定方針で更新する。本体19abd41（0.9.1）のnesdev正確式・32767 unipolar・mixer profile v4を維持し、ホストでDC除去後に49152/32767を掛ける。外部本体とsources.mdは編集しない。

実装前の採否: (1) 0.9.0同期差分に沿うidentity/compat/build/state更新（高効果・低難度、採用）、(2) DC後の整数有理数倍率（高効果・低難度、採用）、(3) 出力変化をadapter識別子とaudio profileへ反映（高効果・低難度、採用）、(4) 独立oracleと保存復帰の検証（高効果・中難度、採用）、(5) 全混合・SMBのクリップ数測定（高効果・低難度、採用）、(6) 9種の既存許容範囲を維持（採用）、(7) 同一入力による再混合・DC分離で残差調査（高効果・中難度、採用）、(8) Nestopia近似式への変更（不採用、確定方針に反する）、(9) 根拠のないDC変更やリミッタ追加（不採用）、(10) 専用スキル新設（不採用、既存試験とリポジトリ内測定手順で再利用できる）。限定した同期・尺度変更のため検討は10案に絞る。

手順: 同期と尺度実装 → Release/Makeの両構成ビルド → 全CTestと9種WAV独立再計算 → SMB600 frames/start@120+4の秒別RMS・クリップ測定 → 残差の原因分離 → 計画とCORE_SELECTION_PLANとvolume-3報告の整合確認。
完了条件は両構成全CTest通過、9種RMS比0.90〜1.10（変更禁止）、既知全混合とSMBの飽和数明示、SMBの残差を測定根拠付きで説明すること。未達はFAILとして原因と次の対応を記録する。クリップ発生時は無断で飽和に依存せずヘッドルーム設計を再検討する。

### ヘッドルーム検証による初期DC仕様の追加

尺度変更だけの診断mixed120 framesで、後半はクリップ0だが起動を含む95842 samples中29 samplesが32767へ飽和した。0.9.1で保持される起動triangle=15のPCM8074に対しDC履歴を0で始めるため、起動DCの減衰過渡が混合音へ加算される。診断で初期dcInputだけ8074へ合わせると最大27415・クリップ0となり、尺度やDC極を変更せずヘッドルームを確保できる。

採用仕様: adapterが初めてpushFrameする直前、audio stateのhasInput=falseのときだけ、最初の実PCMをdcInputへ設定しdcOutput=0の初期定常DC状態から開始する。8074はハードコードせず実入力を用いる。一般Pipelineのステップ応答は変更しない。hard powerは初期化し、既に再生したsoft RESETはDC履歴を保持する。初回出力前のRESETや保存復帰もpendingSlotsとhasInputで同じ初期化を行う。状態フィールド追加は不要でv17/profile2の仕様に含める。リミッタ・倍率低下・フェードは、原因を残すため不採用。

### 残差調査の結論と今回の採用範囲

同一mixed ROMのpulse/triangle分離と、診断Nestopiaのpulse reset timerだけを変える介入で、全混合の主要残差が起動dividerの差による位相関係と確認できた。元のRMS比0.780780は診断変更後1.021930、同tupleの式交換だけでは約0.6%しか変わらない。実機でどちらの起動状態が妥当かは未判定。本体を参照のみとする制約、および基準ROM・閾値維持を優先し、ホストやNestopiaへ位相補正を入れない。

SMBに同じ診断変更をしても全479210 samplesは完全一致する。一方、DCを19HzからNestopiaの0.70Hzへ診断交換すると正確式のまま秒4〜8のRMS比0.962〜0.994、式も近似式へ交換すると1.003〜1.010となる。DMCの遅いDAC変動の除去量もチャンネル分離で確認した。本タスクでは指定された尺度統一と初期ヘッドルーム修正までを採用し、周波数特性自体は19Hzを維持する。0.70Hzへの変更は再生特性の別仕様として測定結果を残す。

検証の目的は合格表示を作ることではなく条件を満たすかを判定すること。9種のうち全混合の位相差が残るため、新コア全CTest合格という完了条件は未達として報告する。最終実測と件数はvolume-3報告へ記録する。

### 0.9.1 最終検証結果

最終Release/Makeビルドは両構成成功。既定CTest33/33（110.98秒）、新コア34/35（411.07秒）。音量9種のうちmixedだけ比0.780780で下限違反、他8種は0.965124〜1.038851。起動を含む全9種・SMBのクリップは0。全混合最大27415、SMB最大14763で、保存WAVの独立再計算が試験ログと一致した。
初期DC、RESET・保存復帰、旧identity/profile拒否、全65536入力の尺度oracleは通過。仕様の閾値・ROMは維持し、未達はmixedの位相差による新コア全CTest合格条件。報告は `docs/reviews/replaynescore-volume-3.md`。本体・sources.md不変、コミット・pushなし。

### 全混合試験の修正とSMBの帯域内評価（2026-10-24、Claude）

- 全混合の不合格は試験の設計の誤り。試験ROMのtriangle周期126（32·127 cycles、約440.4 Hz）がpulse1周期253（16·254 cycles、約440.4 Hz）と同じ周波数で、混合RMSが音量ではなく両コアの起動位相（強め合いか打ち消しか）を測っていた。triangleを周期150（32·151 cycles、約370.4 Hz）へ変えた。周期比127:151は互いに素で、共通高調波はナイキストより上だけになる。許容範囲0.90〜1.10は変えていない。
- 変更後、新コアありctest 35/35、既定33/33。9種のRMS比（後半、WAVから独立計算）: pulse1-15 1.0060、pulse1-7 1.0044、pulse2-15 1.0068、pulse2-7 1.0058、triangle 0.9646、noise 0.9772、dmc 1.0389、pulse-pair 1.0077、mixed 1.0066。全区間クリップ0。
- pulseの起動divider（Nestopia 2048、core 0）のどちらが実機どおりかは未判定。音量の問題ではなく精度の問題として本体側の別件に残す。
- SMBの素のRMS比0.65〜0.72は、ホストの19 Hz DC除去がNestopia（0.70 Hz）の残す19 Hz未満の成分を落とすことによる。両出力に同じ2段1次ハイパスを掛けた秒4〜8の比は、20 Hzで0.963〜0.971、40 Hzで0.968〜0.977、100 Hzで0.978〜0.989。可聴帯域の音量はそろっている。実機NES-001の出力にも約90 Hzのハイパスがあるので、19 Hzは維持し、素のRMSを受け入れ指標にしない。
