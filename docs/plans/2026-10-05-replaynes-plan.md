# ReplayNES implementation plan (2026-10-05)

Spec: `docs/spec/MASTER_SPEC.md`, `docs/spec/DATA_FORMAT_NOTES.md`, step prompts `docs/spec/00..13_*.md`
(the step prompts are scope references; we implement all of them, but in the module order below).

## Fixed decisions (do not re-open)

- App name **ReplayNES**. License **GPL-2.0-or-later** (Nestopia UE is GPL-2+).
- NES core: **Nestopia UE** core (`third_party/nestopia`, git submodule pinned by commit), used through its
  instance-based C++ API (`Nes::Api::Emulator`, `Machine`, `Video`, `Sound`, `Input`, `Machine::SaveState/LoadState`),
  **not** the libretro global API (we need several core instances at once: live play, export, determinism tests).
  Build core sources directly with `NST_NO_ZLIB` (no zlib; uncompressed states). NTSC only in v1.
- Portability: everything except UI/IO glue lives in a **portable C++17 engine** (`engine/`) with **no Apple APIs**,
  exposed through a **stable C API** `engine/include/replaynes/replaynes.h`. macOS app (Swift) uses only that C API.
  Future Windows/Linux frontends (SDL/Qt/Win32) reuse the same engine + C API.
- Build: **CMake** (engine static lib, tests, `replaynes-cli`) works on macOS/Linux/Windows.
  macOS app: **XcodeGen** `apps/macos/project.yml` → Xcode project; it links the engine (either via a CMake prebuild
  step or by compiling engine sources in a static-lib target — implementer's choice, but one source list of truth preferred).
- Vendored single headers OK (MIT): doctest (tests), nlohmann/json. Own SHA-256, CRC32.
- NES button bit order (fixed, versioned as inputFormatVersion=1): bit0 A, 1 B, 2 Select, 3 Start, 4 Up, 5 Down, 6 Left, 7 Right.
  System event flags per frame: bit0 SoftReset, bit1 PowerCycle (applied *before* emulating that frame).
- Frame rate NTSC = 39375000/655171 Hz exactly. Media timestamps: video frame i → i*655171/39375000 s; audio from sample count at 48000 Hz.
- Test ROM: **generated by our own code** (hand-assembled 6502 NROM program in `tests/fixtures/` + CLI `make-test-rom`),
  reading both pads, LFSR RNG in RAM mixed with input, changing bg palette (video) and APU pulse pitch (audio). No third-party ROMs in repo.

## Engine module layout (`engine/`)

- `core/`   ICore interface (loadROM, powerOn, softReset, stepFrame(p1,p2), videoFrame BGRA 256x240, audioFrames int16 mono 48k,
            serializeState, deserializeState, stateHash, coreCompatID). `NestopiaCore`, `MockCore` (frame counter + fake PCM/video).
            Pin deterministic settings: RAM power-on pattern fixed (no random), fixed palette, fixed sample rate 48000, no host time
            (check NstCpu.cpp / board RTC / NstBoardEvent for rand()/time() and neutralize or document).
- `input/`  InputPipeline: physical IDs (strings like `kb:<code>`, `gc:<button>`) → actions (NES buttons P1/P2, Turbo A/B P1/P2, hotkeys)
            via remappable binding table (JSON serializable); analog→D-pad threshold helper; SOCD policy (neutral/last-wins/allow);
            turbo with frame period/duty; hotkeys separated from game input. Output = final p1/p2 bitfields (this is what gets recorded).
- `timeline/` FrameInputLog (per-frame {p1,p2,events}; on-disk: run-length records `varint runLength, p1, p2, events`), Segment DAG
            (immutable segments: id, parentId, startFrame, records), active head, take list, undo history of head switches ("Back to Previous Take").
- `checkpoint/` CheckpointStore: dense recent (e.g. every 30f, bounded) + sparse permanent (e.g. every 600f) + bookmark states;
            metadata {stateID, frameIndex, segmentID, coreCompatID, stateFormatVersion, checksum}. Validity: checkpoint at frame f in
            segment S is valid for a path that contains S with f ≤ (start of S's child on that path).
- `session/` Session: owns core + timeline + checkpoints. Modes RECORD / REPLAY. step(); seek(frame) = nearest valid checkpoint ≤ frame
            + fast replay; recording at frame < take length creates a new branch (old future kept); append at take end extends leaf;
            bookmarks; take switching/undo. Single-threaded: caller serializes calls. Pause/slow/frame-advance pacing is the frontend's job
            and never touches recorded data.
- `persist/` `.nesrec` package dir: manifest.json (formatVersion, appVersion, coreCompatID, coreBuild, stateFormatVersion, inputFormatVersion,
            rom {sha256, lastPath, size}, region), timeline/index.json, timeline/segments/<id>.seg (binary, checksum), states/<id>.state
            (+checksum), metadata/bookmarks.json, journal/ (append-only records since last checkpointed save, CRC per record).
            Atomic temp-write+fsync+rename; manifest written last; open = validate checksums, replay journal, refuse on core mismatch
            (distinct error code), ROM located by path or re-specified ROM verified by SHA-256. Disk-full / corrupt → explicit errors,
            never silent fallback. ROM never stored.
- `render/` OfflineRenderer: new core instance, active-take snapshot (copied, so session can keep changing), runs from frame 0 at
            logical time, yields video frame + PCM per frame; progress; cancel. Hashes comparable with normal replay.
- `harness/` Determinism harness: input script → N runs, compare machine-state/video/audio hash every K frames; run from frame 0 vs from
            mid-savestate; report first diverging frame + component. ≥10000 frames in automated tests.
- `capi/`  `replaynes.h` + impl. Opaque handles, error codes + `rn_last_error()` string, no C++ exceptions crossing the boundary.

### C API sketch (implementer may refine names; keep it C, opaque, thread-unsafe per handle)

```
rn_session* rn_session_new(rom_path, project_dir, &err) / rn_session_open(project_dir, rom_override_or_NULL, &err) / rn_session_close
rn_session_save / rn_session_autosave (incremental, cheap; frontend calls periodically)
rn_set_mode(RECORD|REPLAY); rn_step(s, p1, p2, events, &info) → info{frame, mode, branched, end_of_take}
rn_video(s, &w, &h) → const uint32_t* BGRA; rn_audio(s, &count) → const int16_t* (samples of last step)
rn_frame, rn_take_length, rn_seek(frame), rn_rewind(nframes)
rn_bookmark_add(name)/list/remove/rename; rn_take_count/list(id, length, created_seq)/activate(id); rn_undo_take_switch
rn_input_* (create, bind/unbind/load/save JSON, set_turbo(period,duty), set_socd, set_pressed(id,bool), analog_to_dpad, sample(frame,&p1,&p2,&hotkey_edges))
rn_renderer_new(session) / rn_renderer_total_frames / rn_renderer_next(&video,&audio,&n) / rn_renderer_hash / rn_renderer_free
rn_core_compat_id(), rn_version(), rn_sha256_file(path, out65)
```

## macOS app (`apps/macos/`, Swift/SwiftUI) — after engine

Emulation thread (owns rn_session, paced by host clock only for *when* to step, never *what*), Metal MTKView nearest-neighbor
display, AVAudioEngine source node fed from SPSC ring (mute on pause/rewind/scrub/slow), GameController.framework + keyboard
(NSEvent) → rn_input; controller disconnect → pause. Transport: pause, frame advance, N-frame advance, slow 1/2 1/4, hold-to-rewind,
scrubber, bookmarks, soft reset, power cycle, record/replay, takes ("Rewind to Here" / "Re-record from Here" / "Back to Previous Take"),
export sheet (AVAssetWriter H.264/HEVC + AAC, presets 256x240×N / 1280x960 / 1920x1440(4:3), overscan crop, pixel aspect 1:1 or 8:7),
settings (key/controller remap, hotkeys, turbo, SOCD). Latency instrumentation (input sample → frame emulated → present) shown in debug overlay.
Autosave + crash recovery on launch. Japanese+English UI strings (Japanese primary is fine).
